# Пайплайн «JSON → парсер → карта» и глава 9

План реализации брифа [editor-plan.md](editor-plan.md). Здесь — решения, числа, этапы
и критерии готовности. Код по этому плану: `tools/` (парсер) + `src/json-map.js`
(реализация контракта карты) + `src/levels/level-09.json|js` (данные главы 9).

## 0. Решения владельца (закрыты до кода)

| Развилка | Решение | Что это значит в коде |
|---|---|---|
| Валидатор схемы | **свой, без npm** | правило AGENTS «новых npm-зависимостей нет» не нарушается: Ajv не ставим, `tools/level-schema.mjs` держит описание схемы и проверку руками |
| Куда ложится результат | **парсер пишет JS-модуль главы** | `src/levels/level-09.js` — как остальные главы; `createMap` остаётся синхронным, единственное `await` в жизненном цикле — GLB |
| Форма зданий | **прямоугольные и L-образные** | рёбра `footprint` только по осям; полигон раскладывается в союз прямоугольников; стена = один AABB, физика Чужого и маршруты точные |
| Содержание главы 9 | **все типы объектов на плоской земле** | `terrain.source` (GLB-хайтмап) из брифа в схему не входит: земля — плита; покрыты все enum'ы `roads.type`, `stairs.type`, `rooms.type`, `lights.type` |

## 1. Данные: что разрешено уровню

Бриф просит «универсальный JSON»; ENGINE-контракт сужает его до того, что движок
обещает обитать. Сужение зафиксировано в схеме, а не в комментарии.

Разрешено (верхний уровень ключей — как в брифе):

- `metadata` — `{ levelName, hint, name, units: "meters" }`.
- `ground` — `{ y, size, color }`. Плоская плита: `groundPlane` карты, `size = 176`
  (±88 по обе оси). Пришли к согласию: `terrain` из брифа (`mesh` + GLB-хайтмап)
  здесь не появляется — тип карты с колонками уже держат `TerrainMap`/`ModelMap`.
- `roads[]` — `{ id, type: ground|bridge|embankment, width, points[{x,y,z}], lamps? }`.
  Соседние точки обязаны лежать на одной оси (`dx ≈ 0` **или** `dz ≈ 0`, порог
  `0.01` м): настил дороги — цепочка AABB-коробок. Кривая Катмулла из брифа
  остаётся, но только как **передискретизация** ломаной (сглаживание углов
  перекрёстков), а не как источник поворота: твёрдость обязана совпадать с
  картинкой, а `ExtrudeGeometry` под косым углом дал бы ступенчатую коллизию.
- `buildings[]` — `{ id, name?, floorsCount, floorHeight, baseY?, footprint[{x,z}],
  facadeMaterial?, rooms[], stairs[] }`. `footprint` — простой полигон с рёбрами
  по осям (прямоугольник или L/П-образный: 6–10 вершин).
- `rooms[]` (внутри здания) — `{ id, floor, type: office|corridor|hall|room|cafe|utility,
  polygon[{x,z}], connections[] }`. `polygon` обязан лежать внутри `footprint`
  (проверка парсера) и не пересекаться с `polygon` других комнат **своего** этажа.
- `stairs[]` (внутри здания) — `{ id, connectsFloors[k0, k1], type: straight|l_shape|spiral,
  position{x,z}, rotation?, dimensions{width,length,height?} }`.
- `landscapeObjects[]` — `{ id, model, position, rotation?, scale }` — модели из
  реестра `src/props.js` (`concrete_pillar`, `lamp_post`, `tree`, `bench`, `bollard`).
  Инстансятся, **солидами не становятся** (правило AGENTS о декоре).
- `lights[]` — `{ id, type: point|spot|directional, position, color, intensity,
  distance?, angle? }`. `directional` парсер складывает в `sky.sun` главы
  (второе «солнце» сцене не нужно); `point`/`spot` — настоящие источники,
  собираемые картой, максимум **8** на уровень (`CONFIG.jsonMap.maxRealLights`).
- `sky` / `gameplay` — те же секции, что у прочих глав (`fog`, `hemi`, `sun`,
  `spawn`, `exit`, `exitRadius`, `enemies`, `alienEnemies`, `goal: 'exit'`).

Запрещено и проверяется парсером как ошибка, а не предупреждение:

1. ребро `footprint`/`room.polygon` не по оси;
2. полигон не замкнут (первая и последняя вершина различаются) или имеет
   повторяющиеся соседние вершины;
3. комната вне `footprint` своего здания, комната ⊥ пересекается с комнатой того
   же этажа, комната перекрыта зоной лестницы, которую эта лестница соединяет;
4. `floor ≥ floorsCount`, `connectsFloors` вне `[0, floorsCount)`;
5. лестница вне `footprint`; `spiral` диаметром меньше `2·(radius + CONFIG.radius)`;
6. уклон отрезка дороги больше `maxSlope` (0,3 м/м) — подъём настил держит одной
   наклонной пластиной, а не ступенями, поэтому круче предела неперешагиваемым
   становится весь пролёт (правило пришло на смену паре `maxRise`/`minRun`,
   которая резала уклон на коробки-ступени; `maxRise` остался пределом
   подъёма одной ступени марша);
7. `bridge`/`embankment` с настилом ниже `ground.y + bridgeMinHeight` (1,2 м) —
   под ним нельзя идти, и это уже не эстакада;
8. опора моста, приходящаяся в план наземной дороги;
9. больше 8 источников `point`/`spot`; `castShadow` у них всегда выключен.

## 2. Парсер (`tools/`, Node, без зависимостей)

`node tools/build-level.mjs src/levels/level-09.json [--check] [--out src/levels/level-09.js]`

- **`tools/level-schema.mjs`** — декларация полей (тип, обязательность, enum,
  диапазон) + `validateLevel(raw) → { errors[], warnings[] }`. Пишет человекочитаемые
  сообщения с путём (`buildings[1].rooms[0].polygon[3]`), потому что JSON правит LLM.
- **`tools/normalize-level.mjs`** — геодезическая подготовка. Всё, что клиент не
  должен вычислять сам, считается здесь:
  - замыкание и нормализация полигонов (обход против часовой, удалены дубли,
    целочисленное округление до `0,001` м);
  - `footprint → rects`: раскладка простого полигона с осевыми рёбрами в союз
    прямоугольников горизонтальными полосами по всем различным `z` вершинам
    (для L-образного — 2 прямоугольника, для П-образного — 3);
  - абсолютные высоты этажей: `y = baseY + floor * floorHeight`, перекрытие
    ниже пола на `slabThickness`, крыша над `floorsCount * floorHeight`;
  - `stairs → steps`: `straight` — N ступеней по длине марша (`N = ceil(height / maxStepRise)`,
    rise ≤ `CONFIG.building.stepUp` = 0,6), `l_shape` — два марша с площадкой
    между ними (второй перпендикулярный), `spiral` — `M = ceil(2π / 0,42)` проступей
    по окружности, каждая как AABB; у каждой лестницы — `bottom`/`top` точки
    площадки (нужны для рёбер графа) и `hole` — прямоугольник проёма;
  - вырезы проёмов лестниц из перекрытий: прямоугольник перекрывается
    сеткой 3×3 и сохраняются только клетки вне проёма (иначе проём «закрыть»
    нельзя без дробления плиты);
  - `roads → decks`: для каждого отрезка цепочка коробок `{minX,maxX,minZ,maxZ,
    topY,bottomY}`, на уклонах — со ступенью ≤ `maxRise`; для `bridge` —
    автогенерация опор (`pillarSpacing = 12` м, сечение 1,6×1,6, высота до
    низа настила) в `landscapeObjects`; для `embankment` — тело насыпи
    (коробка от `ground.y` до низа настила) плюс откосы как **геометрия**,
    но не как опора: подняться на насыпь можно только по торцевому уклону;
  - `doors`: `connections[].portalPosition` обязан лежать на ребре комнаты
    (допуск 0,25 м); парсер превращает его в проём стены `[x±doorWidth/2]`
    и точку привязки навигации снаружи здания;
  - `lamps` вдоль дороги: автогенерация `lamp_post` с шагом 20 м по обе стороны;
  - сортировка и стабилизация: одинаковый вход → побайтовый одинаковый выход
    (ключи объектов отсортированы, ГПСЧ не используется).
- **`tools/build-level.mjs`** — CLI: читает raw, валлидирует (`--check` — только
  проверка, без записи), нормализует, пишет `src/levels/level-09.js`:
  `export const LEVEL_09 = { name, hint, map: { kind: 'json', ...нормализованные данные }, sky, gameplay }`.
  В шапке файла — комментарий «сгенерировано tools/build-level.mjs из level-09.json;
  руками не править». Сырой JSON остаётся в репозитории как источник правки.
- **`tools/level-parser.test.mjs`** — прогоны на Node (`node tools/level-parser.test.mjs`):
  схема ловит все 9 запрещённых случаев выше; нормализация детерминирована
  (два прогона — побайтово равный файл); L-полигон → 2 прямоугольника; марш
  3,5 м → 6 ступеней ≤ 0,6; мост 8 м даёт опоры, и ни одна не в плане дороги.

## 3. Клиент: `src/json-map.js` — `JsonMap extends SolidField`

Закрытые члены контракта (`width, depth, spawn, groundHeightAt, isBlocked,
openPositions, worldToNormalized, build, drawMinimap, raySolid, resolveSphere,
rayHitDistance, findPath, randomNavPoint, bounds, solids`) — как у `CityMap`.
Общие механизмы не копируются: `SolidField` (AABB-солиды, плоские опоры,
`bodyClearLine`), `NavGraph`, `stairSteps` из `building.js` (расширен
`r.axis === 'x'`, чтобы марш мог идти и по X — прежние потребители не затронуты).

Что строит из нормализованных данных:

- **стены** — сегменты AABB по рёбрам `footprint` (наружные) и рёбрам комнат
  (перегородки), минус проёмы дверей, с пролётами над дверями; кладутся и в
  `solids` (для `raySolid`/`resolveSphere` Чужого и лучей), и в отдельный
  список `wallBlocks` (для `isBlocked`) — иначе плита, на которой стоишь,
  отбивала бы габарит;
- **перекрытия и полы** — `surfaces` (ходимые) + тонкие solids-плиты; крыша —
  только solid (как в `building.js`, иначе `groundHeightAt(x,z,500)` в ExitGoal
  возвращал бы крышу вместо пола верхнего этажа);
- **лестницы** — проступи: `surfaces` + solids; проём в перекрытии уже вырезан парсером;
- **дороги** — настилы (solids + surfaces верхних коробок), опоры и фонари —
  инстансинг из `src/props.js` (по одному `InstancedMesh` на модель);
- **свет** — `point`/`spot` из данных, добавляются в сцену в `build()`,
  `castShadow = false`, `dispose()` снимает меши, lights и инстансы;
- **навигация** — решётка улиц шагом 6 м с **набором высоты** (`climb`: итерация
  `groundHeightAt`, пока отметка растёт, ≤ 24 проходов), узлы полов каждого
  этажа по прямоугольникам комнат `floor ≥ 1`, рёбра соседям при `|Δy| ≤ stepUp`
  и `bodyClearLine`, цепочка узлов вдоль настилов дорог (иначе пролёт 40 м
  с подъёмом 8 м решётка в 6 м не перешагнёт), рёбра «низ ↔ верх» у каждой
  лестницы по её точкам площадки. Изолированные карманы отсекает `NavGraph`
  (правило AGENTS о единой связной сети).

Миникарта: план этажа, на котором игрок (`y` ∈ [floor·fh, floor·fh+fh)) — стены
из `wallBlocks` по пересечению с этим диапазоном, плюс габарит зданий и полосы
настилов; снаружи — «Улица», внутри — «Этаж k».

## 4. Глава 9 — «Парк путепровода»: все типы объектов

Мир 176×176 м, ночь (небо и туман как у главы 2), цель `exit` из A в B.

| Объект | Данные | Что показывает |
|---|---|---|
| `road_main` | ground, ширина 10, по X при z = 0, y 0,1 | тип дороги `ground`, фонари шагом 20 м |
| `road_cross` | ground, ширина 8, по X = −30 по Z | перекрёсток, проходит **под** эстакадой |
| `road_overpass` | bridge, ширина 9, по Z = −40: (−84, 0,1) → (−44, 8) → (44, 8) → (84, 0,1) | тип `bridge`, уклоны, автоопоры, второй ярус для маршрутов |
| `road_bank` | embankment, ширина 7, по X = 50: (50, 0,1, −70) → (50, 3, −50) → (50, 3, 40) → (50, 0,1, 60) | тип `embankment`, насыпь, откосы |
| `building_plaza` | прямоугольник x 8..38, z 8..34, 2 этажа × 3,5 | `footprint`-прямоугольник, 4 комнаты, вход с `road_main` |
| ↳ комнаты 0 | `hall` (x 8..24), `cafe` (x 24..38) | типы `hall`, `cafe`, перегородка с дверью |
| ↳ комнаты 1 | `office` (z 8..20), `corridor` (z 20..34) | типы `office`, `corridor`, перекрытие с проёмом |
| ↳ лестница | `straight` 0↔1 вдоль x 30..38 | тип `straight`, проём, рёбра графа между этажами |
| `building_l` | L-полигон (6 вершин): x −60..−20, z −34..−6 + отросток x −60..−36, z −6..20, 3 этажа × 3,5 | `footprint`-союз прямоугольников, 3 этажа |
| ↳ комнаты | 0: `utility`, `room`; 1: `office`; 2: `room` | типы `utility`, `room`; третий ярус полов |
| ↳ лестницы | `spiral` 0↔1 (Ø 5,6 м в углу x −58..−52, z −32..−26), `l_shape` 1↔2 | типы `spiral`, `l_shape`; spiral — единственный путь на 1-й этаж, l_shape — на 2-й |
| `building_kiosk` | 12×8, 1 этаж, комната `corridor` + дверь на `road_bank` | маленькое здание под насыпью, дверь на второй ярус |
| `landscapeObjects` | авторские `tree` (6), `bench` (4), `bollard` (8) + автогенерированные `concrete_pillar` (мост) и `lamp_post` (дороги) | реестр моделей, `InstancedMesh`, scale/rotation |
| `lights` | 1 `directional` → `sky.sun`, 4 `point` (площадь, залы), 1 `spot` (под эстакадой) | все три типа источников, лимит 8, тени только у «луны»… то есть у солнца |

Точка A — `spawn` (−72, 60) на юго-западном углу улицы; точка B — пол второго
этажа `building_l` (−48, −14), то есть маршрут обязан пройти: улица → вход →
`spiral` на 1-й этаж → `l_shape` на 2-й. Эстакада и насыпь — открытые альтернативы
(тестируются отдельно: по ним есть путь и под ними можно идти).

## 5. Этапы

Каждый этап заканчивается зелёным прогоном; без него работа не считается сделанной
(правило AGENTS о тестах).

- **Этап 0 — схема и парсер.** Файлы: `tools/level-schema.mjs`,
  `tools/normalize-level.mjs`, `tools/build-level.mjs`, `tools/level-parser.test.mjs`,
  `src/levels/level-09.json` (сырые данные главы).
  Готово: `node tools/level-parser.test.mjs` зелёный; `node tools/build-level.mjs
  src/levels/level-09.json --check` без ошибок; повторный запуск не меняет
  `src/levels/level-09.js` (детерминизм).
- **Этап 1 — JsonMap: каркас контракта.** Файлы: `src/json-map.js`, `src/config.js`
  (новая секция `jsonMap`), `src/game.js` (`MAP_KINDS.json`), `src/levels/index.js`.
  Готово: глава 9 грузится, консоль чистая, `spawn`/`bounds`/`groundHeightAt`
  работают, минимум 20 тестов новой сюиты зелёные (контракт, планировка из данных,
  солиды/опоры, стена держит габарит, дверь пропускает).
- **Этап 2 — комнаты, перекрытия, двери.** Готово: `isBlocked` по перегородкам,
  полы этажей — опоры, проём двери не стена, маршрут «улица → hall → office 1-го
  этажа» существует и физически проходим ногами (шаг-симуляция как в
  `terrain-traverse.test.js`).
- **Этап 3 — три типа лестниц.** Готово: `straight`/`l_shape`/`spiral` дают
  проступи ≤ `stepUp`, проёмы в перекрытиях не перекрываются плитой, граф ведёт
  на все 3 этажа `building_l`, Чужой залезает по фасаду и по потолку залы.
- **Этап 4 — три типа дорог.** Готово: настил `bridge` на 8 м с опорами, под ним
  проход, уклон перешагиваем решёткой узлов, `embankment` непроходим сквозь откос
  (только по торцу), `ground`-улица — опоры; путь A→B по графу и по ногам.
- **Этап 5 — окружение и свет.** Файлы: `src/props.js`, `src/json-map.js`.
  Готово: `InstancedMesh` на модель (число мешей сцены не растёт с числом
  фонарей), 5 реальных источников в пределах лимита, кадр по фотометрии как в
  `night-lights.test.js` (улица под фонарём ≥ 80 sRGB, без света ≤ 45),
  `dispose()` снимает всё.
- **Этап 6 — документация и замеры.** Файлы: `AGENTS.md` (реализаций контракта
  теперь шесть + новый раздел «Данные уровня из JSON» про responsibilities
  парсера, осевые полигоны, лимит огней, не-солидные пропы), `README.md`
  (глава 9, команда парсера, как запускать тесты), этот файл — отметки о замеров.
  Готово: полные 7 сюит браузера + тест парсера на Node зелёные; замеры в
  документе: число солидов, узлов графа, узлов навигации, время `build()`, FPS
  на скрытом канвасе.

## 6. Тесты (`tests/json-level.test.js`, ~26 проверок)

Сюжет покрывает: закрытие контракта; данные главы → геометрия (число зданий,
комнат, проступей); все три типа дорог присутствуют и обитаемы (опора настила,
проход под мостом, откос как стена); все три типа лестниц (подъём ≤ stepUp,
проём не перекрыт, граф ведёт); все шесть типов комнат (пол-опора, перегородка
держит габарит, дверь пропускает); автоопоры моста (есть, стоят под настилом,
ни одна не в плане наземной дороги); инстансинг (один `InstancedMesh` на модель,
`count` = число объектов); источники (≤ лимита, `castShadow` false);
маршрут A→B по графу и по ногам; `raySolid`/`resolveSphere` над настилом и
внутри залы; миникарта; детерминизм (`new JsonMap(spec)` дважды — те же высоты
опор и те же солиды); NaN-вершины.

## 7. Открытые решения (после этапа 0, если что-то не устроит)

- `rotation` у `landscapeObjects` и `stairs` в схеме принимается, но на геометрию
  влияющий только у пропа (поворот вокруг Y); лестницы задаются осевыми
  прямоугольниками. Если нужны косые лестницы — это возвращение к косым
  полигонам и ступенчатой коллизии.
- Проходы (`rooms.polygon`) сейчас обязуются не пересекаться; реальные квартиры
  иногда накладываются (эркер). Правило можно ослабить до «пересечение только с
  лестницей».
- `decor` (пальмы/фонари движка) в главе 9 не вызывается: окружение приходит из
  `landscapeObjects`. Если захочется общий декор — добавить секцию `decor` в
  схему и звать `buildDecor` как `TownMap`.
