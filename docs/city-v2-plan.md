# План v2 генератора города и главы 11 (поворотные дома, дуги, развязка)

Дата: 2026-11-03. Домашний документ для `docs/prompts/004.md` (глава 10) и
последующего запроса: «сделай существующий генератор как v1 и создай v2 для
уровня 11; дома прямоугольные, но под углом к северу; дороги и мосты тоже под
углом; дорога может идти вверх и одновременно плавно поворачивать по окружности;
позже автомобили — дороги должны быть годны для вождения; на уровне 11 развязка:
дорога поднимается вверх по окружности на мост».

## 1. Границы: что такое v1 и что такое v2

**v1** — это ровно то, что стоит в репозитории сейчас: `JsonMap` + парсер
(`tools/city.js`, `tools/normalize-level.mjs`, `tools/level-schema.mjs`) + глава 10
(600×600 м, `kind: 'json'`). v1 **замораживается**: `src/levels/level-10.json` и
`src/levels/level-10.js` не правятся ни на одном этапе v2, а побайтовая сверка
`node tools/build-level.mjs src/levels/level-10.json --check` обязана проходить на
каждом коммите v2, включая правки общего базового класса.

**v2** — новый тип уровня по правилу AGENTS «новый ТИП уровня — новый класс,
реализующий контракт»: `kind: 'json2'` → `JsonMapV2 extends JsonMap`, регистрация в
`MAP_KINDS` ([src/game.js:88](../src/game.js#L88)). Глава 11 — маленькая (~200×200 м),
но с полным набором элементов города и развязкой. Никаких координат главы 11 в
движке и в парсере: всё из брифа.

Поведение, общее для двух версий (пределы ноги, шаг опор, `maxSlope`, `stepUp`,
`radius`), не дублируется: `JsonMapV2` переопределяет ровно то, где появляется yaw
и кривизна.

## 2. Решения владельца (закрыты в этой сессии)

1. **Дуга — sweep, точная.** Полотно описывается осевой линией (дуга/прямая), шириной,
   уклоном вдоль и поперечным наклоном (banking). Коллизия и опора считаются в
   криволинейной системе координат, меш — лента, то есть гладкость картинки не связана
   с числом сегментов. Цепочка прямых пластин отвергнута: излом курса в стыке и
   невозможность банкирования.
2. **v2 = `JsonMapV2` + `kind: 'json2'`**, глава 10 побайтово заморожена, `SolidField`
   получает ориентированные коробки **добавочно**: при отсутствии yaw идёт прежним
   быстрым путём.
3. **Развязка главы 11: R = 40 м, подъём 12 м, ~215°** (7,99 % уклона, длина полотна
   150,1 м).
4. **Банкирование — с самого начала**, числом в данных.

## 4. Модель данных v2

Все новые поля **опциональны** и не появляются в v1-брифах; схема для `kind: 'json'`
продолжает отбраковывать их, чтобы косой дом не мог молча попасть в главу 10.

```
buildings[].rotation        — deg, любой (в v1 марши: только 0/90/180/270, правка не
                              трогается: tools/normalize-level.mjs:322)
roads[].elements[]          — последовательность вместо одного прямоугольника:
    { plate: { x, z, length, width, yaw, rise? } }          — прямая пластина под yaw
    { arc:   { cx, cz, radius, from, to, width, y: [y0, y1], bank?, rails? } }
                              — sweep: дуга с подъёмом и поперечным наклоном
    { connect: 'tangent' }   — парсер сам доводит угол элемента до касательной к
                              предыдущему (G1-непрерывность осевой линии)
bridges[].deck.elements[]   — та же грамматика (пролёт = пластина и/или дуга)
supports: { every, radius }  — опоры вдоль дуги (ступенчатый шаг по θ), отступ
                              `J.pillarEdge` от края остаётся правилом
```

Нормализатор (`tools/normalize-level.mjs`) для `kind: 'json2'`:

- `rotatedRect` → локальные оси `(dir, norm)` + центр, в мировой AABB только для
  broadphase и валидатора;
- `arc` → `{ cx, cz, R, a0, a1, halfW, y0, y1, tanBank, span }` в двойной точности,
  числа в модуль главы пишутся округлённо до 1/1000 (как сейчас для пластин);
- `connect: 'tangent'` разворачивается **парсером**, движок не узнает про
  непрерывность: он получает готовые `a0/a1` и `yaw`;
- секции-переключатели (`windows`, `clutter`, `signage`) наследуются v2 без изменений,
  ряды выводятся в локальных осях дома и поворачиваются на выходе (см. 5.3).

## 5. Движок: где именно появляется yaw

### 5.1 `SolidField` — единственный дорогой потребитель

Базовый класс мыслит строго ось-выровненными коробками: `circleHitsRect`
([src/solids.js:7](../src/solids.js#L7)), хэш по `minX/maxX` (:60), `groundHeightAt`
по «точка в rect» (:85, :113), слэбовый рейкаст с `axis` = ось мира (:136),
выталкивание сферы по минимальной пенетрации вдоль мировой оси (:233, :244).

Правка **добавочная**: у солейда/поверхности/блокера появляется необязательный
`{ c, s }` (косинус/синус yaw). Каждый из шести потребителей получает ветку
`if (o.c === undefined) → прежний путь`, иначе — проекция точки/луча в локальные оси
коробки (2×2 поворот), та же узкая фаза, результат обратно в мир. Математика уже
есть в репозитории в этой форме: `pushOutWedge` и `profileDistance`
([src/json-map.js:2160](../src/json-map.js#L2160)) ровно так считают в локальной системе
призмы. Хэш остаётся по AABB (консервативно для broadphase, точность узкой фазы не
страдает — фантома, запрещённого AGENTS про внешний ассет, тут нет: AABB не пишет
высоту, он только выбирает кандидатов).

Критерий: главы 1–10 проходят зелёным прогоном и побайтовой сверкой, `yaw` ни в
одной из них не задан, поэтому новая ветка не выполняется вовсе.

### 5.2 Что остаётся локальным (и потому дешёвым)

Вся внутренность дома считается в его осях и не меняется: решётка `_refineFloor`,
посадка марша `_landing`, союз прямоугольников кровли и её проёмы, парапет, пороги
дверей, `_clip` ([src/json-map.js:169](../src/json-map.js#L169)) между деталями одного
дома, марши трёх видов. Отсюда — прямое следствие для схемы: **комнаты косого дома
остаются прямоугольными**, как и просил владелец; косой марш внутри косого дома v2
не делает (он остаётся в списке отложенного, п. 9).

### 5.3 Граница «локаль → мир» — одна точка на вывод

Эмиссия дома идёт через `_box` ([src/json-map.js:150](../src/json-map.js#L150)), где
рождаются геометрия, `solids`, `blockers` и `surfaces`: в v2 она же делает
`BoxGeometry.rotateY(yaw)` до `.translate(центр)` и пишет `{ c, s }` в примитивы.
Меши остаются слитыми в буферы по группам (per-building Group не нужен).

Три выводимых ряда (`_windowItems`, `_clutterItems`, `_signageItems` через
`_outerFace`/`_buriedRuns`) считают слоты по рёбрам локального прямоугольника, а на
выходе получают тот же поворот, что и стена: их нормаль `(s, 0, c)` уже хранит ось
грани, достаточно домножить на yaw дома. Тесты «квад снаружи стены / панель снаружи
фасада» переписывать не надо — они рейкастом проверяют факт, а не оси.

Тесты «рядов, которых нет» (влияние другого дома) — единственное место, где yaw чужого
дома заметен: `_buriedRuns` и `_roofCovered` для соседа с yaw берут его AABB
(консервативно: картинка в сомнении не рисуется, коллизия при этом точная).

### 5.4 Sweeps — новая примитив-абстракция дороги

`JsonMapV2.sweeps` — отрезок кольцевого слоя: центр `(cx, cz)`, радиус `R`,
полуширина `halfW`, углы `[a0, a1]`, продольный уклон `k = (y1 − y0) / span`,
поперечный `tanBank`. Публичный член — точная отметка полотна:

```
topAt(x, z) → Δ = (x − cx, z − cz); θ = atan2; ρ = |Δ|
  если θ ∈ [a0, a1] и |ρ − R| ≤ halfW:
    y = y0 + k · R · (θ − a0) + tanBank · (ρ − R)
```

Это же выражение понадобится машинам (`roadFrameAt(s)` — tangent/normal/bank), и
именно поэтому выбран sweep, а не полилиния: у полилинии рамка не непрерывна.

Потребители:

- `groundHeightAt` — по `topAt`, высшая опора в пределах шага ноги (прежнее правило
  `ExitGoal`);
- `raySolid` — пули по **нарезке 5°** (те же 43 полосы, что у меша): отклонение от
  точной поверхности ≤ 0,038 м, зато без решения трансцендентного уравнения луча с
  `atan2`; опора и позиция машины при этом остаются точными;
- `resolveSphere` — расстояние до слоя замкнуто: планарное `hypot(|ρ − R| − halfW)` и
  вертикальное до `topAt` складываются как `hypot` (та же схема, что у призм, и то же
  обоснование «не бесконечные плоскости граней»);
- `isBlocked` — при `rails: true` вдоль дуги ставятся короткие OBB-перила с tangent-yaw
  (замер budget: 215° при шаге 2 м = 150 боксов на обе стороны, при 3 690 солейдах
  главы 10 это +4 % индекса);
- навигация — узлы по осевой линии шагом ≤ `J.navRoomStep` и поперечными рядами, рёбра
  через `_edgeSupported`/`bodyClearLine` (они зовут `groundHeightAt`/`isBlocked`, то
  есть точную `topAt`, и уплотнять их нечем: 0,24 м на 3 м);
- миникарта — `drawMinimap` ([src/json-map.js:1992](../src/json-map.js#L1992)) рисует
  прямоугольники; для sweep — `ctx.arc` по тем же `a0/a1/R/halfW`, для косого дома —
  четырёхугольник из повёрнутых углов.

### 5.5 Валидатор и парсер

Пересечения «дом ↔ настил», «настил ↔ настил», «дом ↔ дом» при любом yaw — SAT для
двух ориентированных прямоугольников (одна функция в `tools/level-schema.mjs`, рядом
с `roadRectsOf`, [:617](../tools/level-schema.mjs#L617)); правило «план дороги у
валидатора и у нормализатора — одна арифметика» распространяется на дугу: `roadRectsOf`
для sweep отдаёт его AABB, а `normalizeRoad` — тот же набор, иначе валидатор начнёт
браковать то, что движок считает проходимым.

## 6. Глава 11 — маленький уровень со всеми элементами

Площадь ~200 × 200 м (`width`/`depth` — данные брифа), `kind: 'json2'`, цель A→B.
Инвентарь (всё, что умеет формат, — по списку секций схемы и выводов):

- `ground` + `waterways` (брод и русло без брода, сходы, береговые стенки), река через
  весь уровень;
- `roads`: наземные (под yaw 0/30/22,5), эстакада на опорах, **развязка** —
  arc R 40 м, 215°, подъём 12 м, banking 6°, перила, опоры каждые 12 м, выход на
  мостовой пролёт через реку; точка B — на настиле моста;
- `buildings`: 8–10 домов, из них 3 вводимых (комнаты, этажи, двери), марши всех трёх
  видов (`straight`/`spiral`/`ladder`), 2 дома повёрнуты (30° и 22,5°), один —
  подиум + башня, один с ходовой кровлей и парапетом;
- `skybridge` между двумя прямолинейными домами (к косому — запрещено валидатором);
- AV-площадка на кровле высокой башни (`av_pad` через `landscapeObjects`),
  рынок/барьеры/контейнеры на тротуарах;
- секции-переключатели `windows`, `clutter`, `signage` — включены все три;
- `lights`: пул ≤ `maxRealLights = 8` + авторские, `sky`/`fog`/`sun`/`hemi` — ночь,
  фотометрия кадра по порогам AGENTS;
- `metadata`, `gameplay` — как в главе 10; `?debug=1` → `debugIds()` с различающими
  суффиксами (`· arc 215°`, `· yaw 30°`).

Бюджет (по правилу «район держат отрисовки и экземпляры»): ≤ 20 мешей, ≤ 15 000
экземпляров, ≤ 120 000 треугольников — уровень вдвое меньше главы 10 по площади.

## 7. Этапы

Каждый этап — отдельный коммит, зелёный полный прогон (после этапа 1 — 158/158)
и побайтовая сверка `level-09.js`/`level-10.js`. Порядок выбран так, чтобы опасное
(общий базовый класс) стояло в начале и проверялось без новых данных.

0. **Заморозка v1.** В `tools/level-parser.test.mjs` — проверка, что `kind: 'json'`
   отбраковывает `rotation`/`elements`; в README — строка «глава 10 = v1, заморожена».
   Код движка не трогается.
1. **OBB в `SolidField`.** Сюита `tests/rotated-solid.test.js` (~10 проверок): коробка
   1×1 под 30° — луч с 8 азимутов, сфера в 30 посадках, опора внутри/снаружи,
   «нет фантомной высоты вне поворота», и главный контроль — при `c = 1, s = 0`
   результаты **равны** прежним побитово.
2. **Косой дом.** `buildings[].rotation` в v2-схеме, `_box` с yaw, выводимые ряды на
   выходе, SAT в валидаторе для дом↔дом. Сюита: дом под 30° проходим (марши, кровля,
   двери наружу), маршрут A→B через косой дом, окна/мусор/неон снаружи стен (рейкастом),
   `debugIds`, глава 10 не двинулась.
3. **Прямые настилы под yaw.** `plate.yaw`, опоры-колонны с tangent-yaw, фонари вдоль
   повёрнутой улицы, валидатор «дом в улице» через SAT.
4. **Sweep: опора и тело.** `sweeps` + `topAt` + `groundHeightAt` + `resolveSphere`
   (самоходный прогон сферы вверх и вниз по дуге — по образцу правила про призмы),
   тест точности отметки против независимого сэмплирования ≤ 1e-6.
5. **Sweep: рейкаст, меш, перила, миникарта.** Нарезка 5°, лента, `rails`, `ctx.arc`;
   отклонение картинки от опоры ≤ 0,05 м по 200 проб.
6. **Развязка.** `connect: 'tangent'`, уклон + banking, мостовой выход, точка B на
   настиле, навигация по дуге (узлы, `_edgeSupported`, отсутствие карманов в
   `_pruneToSpawn`), бюджет.
7. **Глава 11 целиком.** Бриф со всеми элементами п. 6, регистрация в `LEVELS`,
   прохождение A→B автотестом и руками, фотометрия ночного кадра, `?debug=1`.
8. **Правила и журнал.** AGENTS.md — раздел «v2: поворотные объекты и дуги» (OBB
   добавочно, `yaw = 0` быстрым путём; sweep — точная опора, нарезанный луч; banking
   числом; глава 10 заморожена), README — глава 11 и число тестов,
   `docs/prompts/003.md` — отметка запроса.

### Ход этапов

- **1 — готов** (этот коммит): OBB в `SolidField` добавочно — `circleHitsBox` /

  158/158, `level-09.js` и `level-10.js` совпадают с парсером, `obb` ни в одной
  собранной главе не появляется.
- **2a — готов** (этот коммит): половина парсера. `LEVEL_SPEC_V2` — клон v1 ровно с
  двумя полями (`kind: 'json2'` обязательный, `buildings[].rotation` в градусах),
  `validateLevel(raw, spec)` выбирает схему по брифу, `normalizeLevel` пишет
  `map.kind` из него же. Угол ложится **только** в модуль: footprint, стены, комнаты,
  марши и двери нормализатор считает неразвёрнутыми, поэтому весь его союз
  прямоугольников, `subtractRect` и растры остались теми же байтами. В мировой план
  парсер поворачивает там, где решает размещение: `obstacles` (опоры и фонари),
  `makeSupport`, `checkPoints`, `worldBounds` — везде через `obbOf`/`inBox`, а не
  через габарит. Валидатор: footprint × улица и × русло, «за землю» и дом × дом идут
  SAT (`obbHitsRect`/`obbHitsObb`), торец перехода косой дом не отпускает (§ 9),
  пересечение планов разрешено только соосной паре — при одном угле чужой план
  переводится в локальный сдвигом, и прорезание кровли остаётся корректным.
  `src/geo2d.js` получил блок «поворот объекта в плане (v2)» (`frameOf`,
  `rotatePoint`/`unrotatePoint`, `rotatedBounds`, `obbOf`, SAT) — тот же знак, что у
  `BoxGeometry.rotateY` и у `obb` из `src/solids.js`, поэтому движок, картинка и
  валидатор расходятся только если кто-то перепутает математику, а не соглашения.
  Node 83/83 (восемь новых проверок: косой угол, реально легший в улицу, плоский
  дом в той же полосе — норма; пустой угол габарита не бракует улицу; поворот
  выбрасывает дом за землю; соосная пара против разного угла; торец перехода;
  опоры и предупреждения автогенерации; `kind` вне v1-схемы). `level-09.js` и
  `level-10.js` — `--check` совпадает, предупреждений нет.

## 8. Инварианты, которые проверяет план

1. Ветвление по yaw не меняет ни байта в главах 1–10 (побайтовая сверка + прогон).
2. Картинка обязана совпасть с опорой: у sweep это ≤ 0,05 м по выборке, у дома — тот же
   тест, что у призм (самоходная сфера).
3. Никаких фантомов: AABB используется только как broadphase и как консервативный гейт
   картинки, никогда — как высота или как солид.
4. Один источник арифметики плана у валидатора и у нормализатора — распространяется на
   дугу.
5. Машинного кода в движке нет: `roadFrameAt` — только геометрия полотна, физика
   автомобиля появится вместе с ней (чтобы не держать её в двух местах).

## 9. Отложено сознательно

- clothoid/спирали перехода ( arcs достаточно для G1; G2 — когда появятся машины);
- физика и трафик автомобилей, дорожная разметка, знаки;
- косые марши внутри косого дома (ступенчатая коллизия — прежнее ограничение,
  [tools/normalize-level.mjs:322](../tools/normalize-level.mjs#L322));
- стыковка skybridge и прорезание русла/настила повёрнутым домом (валидатор бракует);
- генератор кварталов с косыми лотами: в v2 поворачивается **дом внутри
  прямоугольного лота**, потому что при 30° габарит медианного дома раздувается в 1,92
  раза и в лот не влезает; косая сетка кварталов — отдельный разговор после этапа 6.
