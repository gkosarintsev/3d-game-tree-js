# Правила архитектуры проекта (3D-шутер на Three.js)

Этот файл — источник обязательных ограничений. Любой код, попадающий в репозиторий,
должен им следовать. Если задача противоречит правилу — сначала измени правило
осознанно и обсудив, потом код.

## База

- ES-модули без сборщика. Единственная внешняя зависимость — Three.js 0.160 через
  importmap (CDN). Новые npm-зависимости, сборщики и фреймворки — только по явной
  просьбе владельца проекта.
- Игра и автотесты запускаются в браузере: `python -m http.server 8124` →
  `http://localhost:8124/3d-game.html`. `file://` не поддерживается (importmap).
- Для отладки в консоли страницы открыт `window.game`; модули полагаться на него
  не должны. Отладочное меню главы/параметров — `http://localhost:8124/3d-game.html?debug=1`
  (`src/debug.js`).

## Контракт карты (src/map.js)

- Движок (player, alien, enemies, coins, hud, game, exit) знает о карте ТОЛЬКО
  члены контракта: `width`, `depth`, `spawn`, `groundHeightAt`, `isBlocked`,
  `openPositions`, `worldToNormalized`, `build`, `drawMinimap`, `raySolid`,
  `resolveSphere`, `rayHitDistance`, `findPath`, `randomNavPoint`, `bounds`,
  `solids`.
- Членов контракта два — **опциональных**: `updateStreaming(x, z)` и
  `debugIds()` (первый держит только стримящая карта, второй — карта из брифа,
  где у каждого объекта данных есть свой id). Движок и панель отличают их по
  наличию метода (`typeof`), а не по `map.kind`: главы без них должны работать
  как раньше. `updateStreaming` движок зовёт каждый кадр до физики; пока игрок в
  центральном тайле — `null`, иначе карта перестраивает активное окно и возвращает
  `{ dx, dz }` — метры, на которые окно сдвинулось. Движок обязан на `-(dx, dz)`
  перенести всё, что держит мировую точку (игрока, врагов, точку B, трассеры),
  переставить пул огней на новые опоры и поднять `shadowMap.needsUpdate`, а этот
  кадр симуляции не вести: сборка окна занимает 130–470 мс, и считать по уже
  перенесённом мире незачем. Отличать карту со стримингом по наличию метода, а
  не по `map.kind`: главы без него должны работать как раньше.
- Новый ТИП уровня — новый класс, реализующий контракт; `map.kind` из
  определения главы выбирает его в `Game.createMap()`. Реализации сейчас шесть:
  `TownMap` (улица с домами), `TerrainMap` (src/terrain-map.js: сложный
  рельеф — холмы, горы с пещерами, пропасти, мосты; домов нет), `CityMap`
  (src/city-map.js: сетка кварталов с домами — глава «ночной город»), `ModelMap`
  (src/model-map.js: глава из внешнего GLB-макета города — твёрдость извлечена
  из его меша в сетку колонок), `StreamedModelMap` (src/stream-map.js: тот же
  макет, но крупнее одного района — твёрдость приходит активным окном и
  переставляется по ходу пути; наследник `ModelMap`, ничего не дублирующий) и
  `JsonMap` (src/json-map.js: уровень, собранный из брифа — дома с комнатами,
  этажами, маршами трёх видов, ходовыми кровлями и дорогами трёх типов; числа и
  топологию считает Node-парсер `tools/normalize-level.mjs`, здесь остаются
  AABB-солиды, аналитика наклонных призм (пролёты настила и откосы насыпи), опоры,
  коллизии габарита, граф и меш). Один класс обслуживает оба вида брифа —
  `json` (v1, оси мира) и `json2` (v2: поворотные дома и настилы, дуги; см.
  раздел «v2: поворотные дома, настилы и дуги»).
  Общий механизм AABB-солидов (рейкаст, сфера, маршевый луч), плоских опорных
  поверхностей (`surfaces` + `groundHeightAt`) и проверки ребра графа для тела
  (`bodyClearLine`) — базовый класс `SolidField` (src/solids.js); граф навигации
  и поиск маршрута — `NavGraph` (src/nav-graph.js); генератор дома, его геометрия,
  коллизии, опоры и подграф полов — src/building.js. Всё это переиспользуется без
  копий: новый тип карты обязан строиться на тех же общих механизмах.
- Изменять сигнатуры методов контракта можно только вместе со всеми
  потребителями и автотестами.
- Граф навигации держит **одну связную сеть** точек, куда враг доходит пешком.
  Изолированные карманы (двор внешнего макета, отрезанный башнями) отсекаются при
  построении графа: внутри себя они проходимы, проба габарита их не бракует, но
  маршрута наружу не имеют — возрождённый там враг стоит на месте, а точка
  объекта легла бы туда, куда человек не дойдёт.
- Случайная точка блуждания (`NavGraph.randomPoint`) собирается одним проходом по
  узлам в радиусе, а не серией случайных угадок в весь список: на большой карте
  доля узлов рядом с точкой мала (на районе 700×700 м в круг 55 м попадает ~2%
  списка из 8,4 тыс. узлов), угадка почти всегда мимо, `randomNavPoint` даёт
  `null`, целью блуждания становится собственная позиция врага и патруль замирает.
- Декор (`src/decor.js`) — чистая визуальная геометрия: не создаёт `solids`, не
  участвует в `isBlocked` и навигации. Коллизии и проходовость уровня не зависят
  от украшений.

## Внешние ассеты уровня (GLB)

- Готовую геометрию в проект приносит только `.glb`, прочитанный `GLTFLoader`
  из importmap через `src/glb.js` (кэш по URL, разбор сцены в типизированные
  массивы треугольников: `pos`, `ny` — доля вертикальности). npm-пакеты
  коллизий (three-mesh-bvh и т.п.) для этого запрещены.
- Твёрдость внешнего ассета извлекается в **те же общие механизмы**, что и
  геометрия, нарисованная движком: сетка колонок шагом `cell` из определения
  уровня, верх колонки — максимум перекрывающих её треугольников, `isBlocked`
  и `groundHeightAt` работают по колонкам (пределы — `CONFIG.building.stepUp`
  для человека и `CONFIG.alien.stepUp` для Чужого, те же, что на всех картах).
  `solids` при этом остаётся пустым, а `raySolid`/`resolveSphere`
  переопределяются маршем по колонкам — ровно как аналитический верх у рельефа:
  чужая модель не должна превращаться в тысячи AABB, раздувающих индекс.
- Колонки растеризуются из **тех же треугольников, что и картинка**, и про
  каждый треугольник решение одно по его **собственной XZ-проекции**: обычная
  грань (крыша, пол, наклонная плоскость) пишет высоту своей плоскости в центр
  каждой клетки, чей центр лежит внутри проекции; грань с вырожденной
  проекцией — отвесная стена-«лента» (площадь проекции почти нулевая, так в
  макетах рисуют фасад без толщины) — обходит свой отрезок по сетке (DDA) с
  запасом в полклетки и пишет максимум по высоте. Габарит (прямоугольник вокруг
  проекции) запрещён: на макете главы 3 он дал 49 027 фантомных клеток из
  207 686 занятых (23.6%) — невидимые башни до 116 м вокруг каждого косого
  фасада, в которые упёрлись и маршруты врагов, и лазанье Чужого. Запас в
  полклетки держит стену непрерывной (соседние клетки сходятся по стороне, а не
  по углу), поэтому невидимого зазора, в который проваливалось бы тело, не
  остаётся — прежняя цель консервативности сохранена без её побочного эффекта.
- Огромные плоскости (плита-земля макета) в колонки не пишутся: их заменяет
  `groundPlane`/`groundY` из данных главы. Растеризация покрышки в 25 км²
  забивает сетку колонок и не даёт ничего, кроме медленной загрузки.
- `resolveSphere` района выталкивает сферу **по собственному верху каждой
  клетки**, а не по максимуму соседних. Полка, невидимая колонке (свес уступа
  достаёт до клетки, чей центр под него не попал), провоцирует раздуть коробку
  соседями — это запрещённый тем же правилам фантом: у соседних с башней клеток
  улицы колонка вырастает от плиты до её верха, и тело, которое должно идти по
  асфальту, выталкивает вбок. Замерено на главе 3: из 464 свободных клеток улицы
  58 (12,5 %) сдвигали Чужого в сторону на 3 м, а подъём по отвесному фасаду
  вообще переставал начинаться (максимум `y = 3,33` против `83,02` на той же
  сетке) — тело не дотягивалось до стены. Единственная высота на клетку не умеет
  «пол сверху и воздух снизу»; лечится она не раздутием колонок, а многоуровневой
  колонкой или клеткой мельче в окне подъёма.
- Окно района, масштаб, спавн и точка B — **данные уровня** (`asset`,
  `window`, `scale`/`scaleFrom`, `spawn`), центр окна становится (0, 0) мира
  главы. Координат конкретной главы в `model-map.js`, `stream-map.js` и `game.js`
  быть не может.
- Сетка колонок детерминирована: один и тот же ассет и окно обязаны дать
  бит-в-бит одинаковые высоты (проверяется автотестом). Растерка читает **сырые
  координаты файла** и вычитает центр окна в двойной точности, а не округлённые до
  float32 локальные метры: у нескольких граней макета площадь XZ-проекции сидит в
  шаге float32 от порога `wallArea`, и при другом центре окна она переходит порог
  в другую сторону — на главе 4 прежний путь давал 13 клеток из 405 600 с разным
  вердиктом «стена», то есть невидимую башню высотой 32 м, которая то появляется,
  то исчезает на стыке тайлов. В mesh идут локальные float32 (рендеру нельзя
  стоять на координатах ~2000 м), в твёрдость — файловые двойные.
- Макет крупнее одного района стримится (`src/stream-map.js`), и тогда **для
  движка уровень = активное окно**: `width`/`depth`/`bounds`/`worldToNormalized`
  держат размер окна (780 м), а не габарит города, — обзорная камера, карта теней
  и миникарта продолжают работать в масштабе района. Целиком макет открыт только
  полем `cityBounds` (метры масштабированной модели): оно нужно данным главы и
  границам стриминга, движку оно не требуется. Колонки клеткой 1 м на весь макет
  запрещены — это 74 МБ и полмиллиона узлов навигации, которые никто не ходит
  дальше района; вместо них окна собираются из корзин треугольников по тайлам
  (`tileBuckets` в src/glb.js).
- Перестановка окна кратна **тайлу** (сторона `tile` — целое число клеток `cell`),
  а сторона окна — нечётное число тайлов: иначе решётка колонок меняет фазу, и два
  окна сравнивают разные клетки (замер: сдвиг на 100 м — 0 различий из 530 400
  клеток, сдвиг на полклетки — 13 667, 2,2 %). Окно целиком за пределами плиты
  макета не собирается: опирать улицу не на что.
- Плита макета (её отметка и прямоугольник, измеряются один раз за главу по
  крупным горизонтальным граням всего файла) ограничивает проходимость: за её
  краем `isBlocked` истинна, иначе колонки пусты, но `groundY` отвечал бы опорный
  верх, и улица продолжалась бы в несуществующий район.
- Враги стоят на опорах **активного окна**: после перестановки `Enemies` проверяет
  каждого по `bounds` и, кто остался за бортом, снимает со сцены **молча** — без
  анимации смерти, звука и засчитанного убийства (в отличие от `_die()`), — и
  ставит в уже существующую очередь возрождения; возрождённый берёт узел нового
  графа. Такой враг исключён из `raycast` и из миникарты: стрелять в несобранный
  район и показывать точку, куда человек не дойдёт, нельзя.
- Перестановка окна — это перестройка, а не накопление: меши старого окна снимаются
  со сцены и `dispose()`-нятся на каждой перестановке, а возврат к прежнему центру
  обязан дать тот же верх колонок, что и первый раз (проверяется автотестом).
- Загрузка ассета — единственное разрешённое `await` в жизненном цикле уровня:
  `_loadLevel` вызывает `await preloadMapAsset(map)` перед `createMap` и
  показывает состояние `'loading'` через `hud`; `createMap`/`createModelMap`
  остаются синхронными и работают с кэшем. Главы без ассета грузятся как раньше
  (preview-сцена меню — синхронная). Всё, что нужно после `await`, обязан брать из
  **своих локальных** данных (`index` и определение главы, захваченные до `await`),
  а не из `this.level`: вызовы `_loadLevel` могут наложиться (меню `?debug=1` зовёт
  его по клику, а главы 3 и 4 стоят подряд на одном GLB), и сборка «текущей» главы
  тогда строит карту, ассет которой ещё не прочитан.
- Каждый внешний ассет коммитится только с атрибуцией: лицензия и автор — в
  `README.md` и в комментарии определения уровня. Ассет без лицензии не появляется.

### Ночный вид макета и свет главы

- Ночь уровня — **данные**, а не особые ветки в коде карты: `map.albedo`
  (диффузия макета), `sky.lights` (пул огней), `sky.sun`/`sky.hemi` («луна») и
  `sky.fog` перечислены в определении главы; `ModelMap._applyAlbedo()` и
  `NightLights` читают их и не знают номеров глав.
- Материалы ассета лежат в кэше `GLTFLoader` и переживают повторные сборы меша,
  поэтому правка цвета обязана быть **идемпотентной**: новый цвет собирается из
  исходного (`userData.dayColor`), а не умножается на текущий. Второй `build`
  той же главы не имеет права затемнять дальше (проверяется автотестом).
- Расписывать окна эмиссией «по имени материала» можно только если у этого
  материала есть поверхность. В макете главы 3 это проверено и запрещено: карт
  эмиссии в файле нет вообще (`emissive` = 0x000000 у всех материалов), текстуры
  несёт только плита `material_0` плюс `Plaster` с `CorrogateRust` — окон не
  рисует ни одна. Из 56 материалов района площадь ≥ 1 м² держат **4** (общий
  `material` на здание целиком, `Color_M00`, `0128_White` и плита `material_0`),
  а все именные цветные акценты (`Color_D05`, `Beige_1`, `Color_I0x`, `Color_H0x`,
  `material_69`) — это линии нулевой площади: 3440 «фасадных» граней дают 0,1 м²
  на все. Общий материал не различает фасад и остекление, поэтому эмиссия по нему
  подсвечивает здание целиком (замер: `emissive` на всех материалах меняла кадр с
  56 до 221, то есть район светился как днём). Светящиеся окна возможны только как
  **отдельная фича** — процедурные квады окон по данным колонок; прежде чем делать
  её, решение за владельцем проекта.
- Ночной свет держит **пул настоящих источников** (`src/night-lights.js`), а не
  lamp на каждый фонарь: точечный свет — множитель в каждый фрагмент, а район
  главы 3 — 51 тыс. граней. `count` огней переставляются на ближайшие опорные
  точки из `map.openPositions()` (только члены контракта карты), разносятся не
  ближе `spacing` и поднимаются на `height` над опорой; `update()` трогает их,
  только если камера ушла дальше `reprobe`. Пул добавляет объекты в сцену, поэтому
  обязан иметь `dispose()` и сниматься в `_initScene` при каждой загрузке главы.
- Тени у огней пула выключены (`castShadow = false`), «луна» — единственный
  источник теней, карта теней заморожена (`shadowMap.autoUpdate = false`).
- Проверка ночного кадра — фотометрия, а не «на глаз»: сцена рендерится в
  `WebGLRenderTarget` (`FloatType`), пиксели читаются `readRenderTargetPixels` и
  пересчитываются в sRGB (в не-XR мишень r160 пишет **линейные** значения).
  Строки буфера идут снизу вверх. Пороги читаются так: улица под фонарём 80, без
  огней 40, фасад 39…65, небо 15 (sRGB).

## Уровни — это данные (src/levels/)

- Каждая глава — один файл-определение: `name`, `map` (kind и содержимое уровня),
  `decor`, `sky` (sky/fog/sun/hemi), `gameplay` (цель, монеты/выход, число
  врагов). Регистрация — в `src/levels/index.js` массивом в порядке прохождения.
- Первые четыре главы — переходы «из точки A в точку B» (Half-Life-логика без
  сбора монет): цель `gameplay.goal: 'exit'`, точка B — `gameplay.exit`.
  Глава 2 — ночной город (`map.kind: 'city'`, сетка кварталов), глава 3 — тот
  же ночной город, но новый район из GLB-макета (`map.kind: 'model'`), глава 4 —
  весь макет тем же файлом, но активным окном с перестановкой по ходу пути
  (`map.kind: 'stream'`). Главы 5–8 (сдвинутые прежние) остаются уровнями-улицами
  с целью `'coins'`, глава 9 (`map.kind: 'json'`) — переход A→B из брифа.
- Главы 9 и 10 несются пайплайном «JSON → Node → движок»: автор правит
  `src/levels/level-09.json` и `src/levels/level-10.json`, `node tools/build-level.mjs <путь>`
  валидирует их (`tools/level-schema.mjs`), нормализует (`tools/normalize-level.mjs`)
  и пишет `src/levels/level-NN.js`. В репозитории живут оба файла; модуль —
  производное, его совпадение с парсером проверяет `tools/level-parser.test.mjs`
  (73 проверки, `node tools/level-parser.test.mjs`); закоммиченный модуль обязан
  сходиться побайтово **и не нести предупреждений парсера** — предупреждение в
  собранной главе значит, что геометрию отдали обходному пути и в браузере её не
  видно. `JsonMap` не знает ни номера главы, ни схемы: он ест нормализованные
  данные, как остальные типы едят свою map-секцию.
- Светящиеся окна фасадов — **выводимая картинка, а не запись в модуле**: секция
  `windows` в брифе включает механизм, `JsonMap` сам расставляет квады по рёбрам
  своих фасадных стен. Список положения каждого окна парсер не пишет: 32,6 тыс.
  записей удвоили бы файл главы, а вывести их можно из чисел, которые уже есть.
  Сам факт секции — переключатель (главы без неё обязаны собраться побайтово как
  раньше), числа — `CONFIG.jsonMap.windows` с переопределением ритма по
  `facadeMaterial` (`byMaterial`), а не литералы в модуле. Меши инстансятся **по
  одному на цвет палитры** и берут `MeshBasicMaterial`: узкое место района —
  отрисовки и экземпляры, а не треугольники, и окну не нужен свет сцены, оно и
  есть свет. Квад не создаёт ни `solids`, ни `blockers`, ни узлов графа: он висит
  снаружи грани стены, а решение о проходимости принимает эта стена (правило
  про декор).
- Мусор кровель и тротуаров (`vents`, `кондиционеры`, `баки`, `барьеры`, ящики) —
  **тот же вывод из тех же чисел**, что и окна: секция `clutter` включает
  механизм, `JsonMap` расставляет предметы сеткой по своим кровлям и настилам и
  отдаёт их in-memory список `props`'у, поэтому модуль главы не растёт. Предмет
  бракуется, если над ним нет запаса `head` (иначе коробка вентустановки садится
  в проём перекрытия), если его перекрывает план другого дома, если он попал внутрь
  плана или ближе `minLamp` к фонарю, и если `groundHeightAt` не сходится с отметкой
  настила (проход по плите дороги — не тротуар). Меши инстансятся **по одному на
  пару «тип + материал»**, материалы модульные (`src/props.js`) и переживают
  загрузку следующей главы, поэтому `dispose()` обязан снимать геометрию, но не
  их. Детерминизм выводим: отсчёты ГПСЧ, снятые с **соседних целых** (`k` и
  `k + 1`), коррелируют в старших битах, и гейт плотности выбирал тогда почти
  только первые два типа из четырёх (замер: `[2989, 2928, 73, 82]` против
  `[1586, 1446, 1497, 1543]`) — цепочка обязана идти через один солёный шаг на
  каждый следующий отсчёт (`makeDraw`), а не через `fnvMix(hb, k + 1)`.
- Вывески и неон фасадов — **третий вывод того же ряда** (`windows` → `clutter` →
  `signage`): секция `signage` включает механизм, `JsonMap._signageItems()` ставит
  панели по тем же `_outerFace()` и `_buriedRuns()`, что и окна, меши — один на
  цвет палитры, в сцену добавляется `userData.quad = 'signage'` (класс материала
  у обоих рядов общий, поэтому ряды различаются именно этим полем, а не именем).
  Панель бракуется, если перекрывает чужой объём, попадает на дверной проём этажа
  или не влезает под кровлю, а слотов на грани не больше `perFace`: иначе фасад
  становится обоями. Таблица `byMaterial` — **надстройка над базой**, а не замена:
  слияние `{ ...S, ...style }` возвращает `keep`/`width` материала, и настройка
  брифа тогда молчит (замер: 63 панели и при `keep = 0,4`, и при `keep = 1`),
  поэтому в дефолтной таблице живут только исключения, а общий ритм задаётся из
  брифа. Вертикальный пояс панели обязан быть клампован по `floorsCount − floors`:
  без него у 4-этажных домов (их большинство) пояс всегда вылезал за кровлю, и
  плотность переставала слушаться `keep`.
- Кварталы генератора (`city` в брифе) разворачивает **парсер**, а не движок:
  `tools/build-level.mjs` вызывает `expandCity` (`tools/city.js`) до валидатора,
  поэтому `validateLevel`, `normalizeLevel` и `JsonMap` видят обычный уровень из
  `buildings`/`roads`, а служебная секция `city` в модуль главы не попадает.
  Генератор обязан оставаться детерминированным: единственный источник
  случайности — ГПСЧ с `city.seed`, а **порядок его вызовов значим** (снять один
  гейт — значит сдвинуть счётчики всех последующих районов, поэтому перегенерированный
  модуль коммитится вместе с правкой), и размеры лота, отметки и план марша никогда
  не берутся из `Math.random`.
- Авторская запись вытесняет сгенерированную по id **и по префиксу `<лот>_`**: id
  генератора строится как `<id района>_<номер лота>` с суффиксом части, поэтому
  правка одного дома в `buildings[]` не требует править район, а надстройки его лота
  не остаются сиротами.
- Тесная комната — норма генератора, а не исключение: середина плана занята
  шахтой марша, а полоса габарита у стены съедает `radius + wallThickness / 2`,
  поэтому решётка `J.navRoomStep` в доме 6–8 м глубины даёт одну-две живые линии.
  Поэтому `JsonMap` мельчит сетку комнаты, давшую ≤ 2 клетки, тянет по ней посадку
  марша (`_refineFloor`) и дотягивает кровлю от люка (`_roofChain`), а наружный узел
  **внешней** двери связывается только с узлами вне плана дома: три самых близких
  кандидата — клетки пола той же комнаты, и без фильтра дом остаётся связным
  внутри, но отрезанным от улицы, и целиком
  выбрасывается `_pruneToSpawn` (двери между комнатами фильтра нет — их наружная
  точка стоит внутри плана, и цель их — соединять интерьер).
- Доля вводимых домов района — **данные** (`city.districts[].enterableEvery`), а не
  константа генератора: лот-кандидат (ровно один прямоугольник плана, не башня)
  открывается каждому `N`-му, и смешение частоты по районам (2 в жилом, 3 в деловом)
  поднимает число интерьеров без раздувания модуля (замер главы 10: 28 вводимых домов
  и 11 кровель против 8 и 4 при частоте 8 — размер модуля +6 %, прогон парсера
  130 мс).
  Отказ открыть лот считается счётчиком (`house_not_rect`, `house_no_stair`,
  `house_no_entrance`), а не молчанием: «дом не стал вводимым» без причины нельзя
  ни проверить, ни починить.
- Ребро графа `JsonMap` держит не только габарит (`bodyClearLine`), но и опору
  под каждым шагом (`_edgeSupported`, пробы `J.navEdgeProbe`, провал глубже
  `J.navEdgeDrop` бракует ребро): отрезок «верхняя ступень → клетка пола через
  весь веер нижних» свободен для тела, но под ногой там проём перекрытия, и
  идущий падал с этажа на грунт. У каждого марша поэтому есть посадка — узел
  пола этажа сразу за его планом (`_landing`), и уже она связывается с решёткой
  комнаты; без неё у верхней проступи не было бы соседа на своём этаже, потому
  что проём в плите шире, чем шаг решётки комнаты. Ребро двустороннее, поэтому
  проба идёт в **обе** стороны, а нога не поднимается выше концов ребра
  (`_edgeWalk`, потолок `max(a.y, b.y)`): без потолка проба внутри шахты видит
  следующую проступь, и спуск с неё за край шахты давал провал глубже
  `navEdgeDrop` — законное ребро «пол → первая проступь» браковалось.
- Отступ линии решётки от грани плана — `CONFIG.radius + J.wallThickness / 2 + 0,05`,
  а не просто радиус: стена (и парапет кровли) стоит **серединой** на линии полигона
  и лезёт внутрь на половину толщины, поэтому клетка в `radius + 0,05` от грани
  всегда внутри габарита и бракуется — целая линия решётки. На доме 14,5 × 6 м
  главы 10 (`nkab_094`) из-за этого живала одна линия клеток, и она попадала ровно
  в полосу шахты марша: этаж рассыпался на две несвязные половины, и `_pruneToSpawn`
  отрезал весь верх дома вместе с вторым маршем. То же правило для кровли: парапет —
  фасадная стена той же толщины.
- Дорога с перепадом высот — **одна наклонная пластина на отрезок**, а не лестница
  коробок: крутизну ограничивает схема (`|rise| / run ≤ J.maxSlope`, иначе ни ноги,
  ни сфера Чужого подъём не перешагнут), а её верх — аналитическая плоскость
  `y = k·u + c`. В `solids` пролёт не попадает: коробка по его низу спрятала бы
  под гладкой картинкой ступени, которых глаз не видит, — ровно как аналитический
  верх рельефа в главе 1. Его держат переопределённые `groundHeightAt`, `raySolid`
  и `resolveSphere`; узлы графа на пролёте ставятся чаще решёточного шага, чтобы
  перепад соседних узлов не превысил `stepUp`.
  Марши лестниц так и остаются коробками ступеней: у них подъём и есть картинка.

### v2: поворотные дома, настилы и дуги (`kind: 'json2'`)

- v2 — **те же данные и тот же `JsonMap`**, а не второй класс: общие механизмы
  (солиды, опоры, призмы, граф) уже существуют, и различие живёт только в полях
  брифа, которые схема `json2` разрешает. Главы v1 (`level-09`, `level-10`)
  заморожены: их модули обязаны побайтово совпадать с парсером, а схема v1
  отбраковывает поля v2 явно, чтобы косой бриф не собрался молча прямоугольником.
- Поворотный дом (`rotation`) считает стены, комнаты, шахты маршей и проёмы
  дверей **в своих осях**, а мир получает через кадр поворота и OBB (`src/solids.js`).
  Габарит в коллизиях запрещён: он накрыл бы невидимыми стенами пустые углы.
  Пересечение планов разрешено только соосным домам (одинаковый `rotation`), и
  это проверяет SAT-валидатор.
- Пластина настила (`{plate}`) задаёт `y` — верх на **локальном начале**
  (`u = −length/2`), `rise` — перепад до локального конца; `topAtMin/topAtMax`
  относятся к локальным концам, а `minX/maxX` — мировой габарит, и у пластины
  с `yaw = −180` начало смотрит на восток. Всякий, кто проверяет пластину,
  обязан пересчитать локальный конец в мир, а не сравнивать его с `minX`.
- `connect: 'tangent'` переносит **только угол** (касательную предыдущего
  элемента), позицию следующей пластины автор задаёт сам: у маркера нет
  координат. В цепочке `prev` — уже **разрешённый** элемент, иначе второй маркер
  подряд получает авторский `yaw` вместо вычисленной касательной.
- Дуга (`{arc}`) — точная поверхность по углу, радиусу и крену (`bank`), а не
  набор хорд: меш-лента и луч режутся по одной нарезке, поэтому картинка, опора
  и попадание пули сходятся. Узлы графа идут по осевой дуги; перила бракуют
  край, но не осевую.
- Сфера на наклонной пластине выталкивается **по нормали** (расстояние до
  плоскости равно радиусу), поэтому её вертикальный зазор над плоскостью —
  `r / cos уклона`, а не `r`. Проверка «сфера на горизонтали» к наклону
  неприменима.
- Шахта марша на кровлю ставится так, как её ставит генератор, — **в угол у
  двух внутренних граней**: посадка выходит наружу от шахты, и `_roofChain` идёт
  туда же. У фасада полоса кровли уже отступа решётки, цепочка упирается в
  парапет, ребро через проём шахты бракует `_edgeSupported`, и кровля целиком
  уходит из графа.

- План дороги у валидатора и у нормализатора — **одна арифметика**: `roadRectsOf`
  обязана отдавать ровно те пластины, что считает `normalizeRoad`, включая их
  торцы. Наращивание плана на полширины вдоль оси (прежняя «крышка» торца) давала
  24 ложных «дом стоит в улице» на развёрнутом городе главы 10, где тупики улиц
  обрамлены кварталами, и расходилась с данными, по которым собираются меш и опоры.
- Фонарь сбрасывается в русло только у **наземной** улицы: настил моста и эстакады
  сам держит свою опору света над водой, и правило, одинаковое для всех типов
  дороги, молчало восемнадцатью предупреждениями на трёх мостах главы 10.
- И наклонный пролёт настила, и **откос насыпи** — одна и та же абстракция:
  `JsonMap.prisms`, выпуклый профиль `(u, y)`, протянутый поперёк на `[v0, v1]`
  (плита — four вершин, откос — три). Откос держит опору, луч и сферу тем же
  механизмом и **не** попадает ни в `solids`, ни в `blockers`: коробка во всю
  высоту откоса рисовала прямоугольник вместо скоса и превращала шаг за край
  полотна в падение в грунт, из которого нет дороги. Верх откоса обязан
  совпадать с **верхом** настила (не с его sole) и заложение брать из
  `J.apronRun` по этой отметке: иначе сойти с полотна можно, а вернуться —
  ровно шагом `J.deckThickness` вровень с `stepUp`, и на этом шаге застреваешь.
  Сферу выталкивать по **точному расстоянию до призмы** (расстояние до профиля
  и до интервала поперёк складываются как `hypot`), а не до бесконечных плоскостей
  её граней: у пятки подъёма ближайшей гранью оказывался вертикальный торец,
  и тело упиралось в невидимую стену там, где глаз видит начало склона
  (проверяется самоходным прогоном сферы вверх и вниз по каждой призме).
- Опоры моста (`bridge_pillar`) стоят **под настилом**, а не сбоку: ряд отступлён
  от края пластины на `J.pillarEdge` (и сходятся в один, если отступить некуда),
  их не ставят под наклонным пролётом и под пластиной, помеченной `grounded`
  (она опирается на грунт насыпи, и колонны под ней — мусор в картинке).
- Кровля дома — **данные, а не особая ветка**: плита лежит на союзе прямоугольников
  footprint, прорезанном шахтой марша, выведенного на кровлю, габаритом здания,
  выросшего из неё (подиум + башня), и планом примыкающего настила. Опорой
  (`surface`) плита становится **только при `roof.walkable: true`**: `ExitGoal` берёт
  отметку точки B как `groundHeightAt(x, z, 500)` — сделай опорой любую крышу, маяк
  главы переехал бы на кровлю дома, под которым стоит улица. Ходовую кровлю по внешнему
  краю держит парапет — блокер полосы `[roofY, roofY + parapet]` в плане фасадных стен:
  он бракует и узел решётки, и сход с плиты, но не мешает тому, кто идёт ниже своей
  отметки. Где к кровле примыкает настил перехода, в парапете обязана остаться дыра
  **его планом, растянутым вдоль оси настила на толщину стены** — обрезка собственным
  (узким) планом режет полосу вдоль, а не поперёк, и проёма не выходит. Пробовать
  опору кровли обязан тестом **с отметки самой кровли** (`groundHeightAt(x, z, roofY)`):
  член отдаёт высшую опору в пределах шага ноги, и проба на метр ниже отвечает полом
  этажа под плитой, выдавая рабочую геометрию за сломанную.
- Вертикальный марш (`ladder`) — **не лестница, а шахта**: план `J.ladderShaft` по
  умолчанию (из `dimensions` его не берут), все проступи лежат в одном плане и
  различаются только отметкой верха, подъём одной — ≤ `J.maxRise`, верхняя приходит
  ровно на `y1` (этаж) или `roofY` (люк). Низ каждой проступи — на её толщине
  `J.ladderRung`, а не на полу шахты: столб от пола до верха перекрывал бы проход
  тому, кто ещё на середине.
- Переход (`skybridge`) — настил **без опор с земли**, его держат здания: каждый
  торец обязан совпасть (допуск `J.skybridgeFit`) с полом комнаты, чья дверь выходит
  на план настила, или с ходовой кровлей. Валидатор проверяет торец по **концу
  пластины** (`endCap`), а не по пластине целиком: у прямолинейного перехода одна
  пластина на оба конца, и свисяющий дальний торец иначе прошёл бы проверку.
  Торец отпускается в плане на тот же `J.skybridgeFit` (`grown`), а дверью считается
  **проем** (`door.rect`), а не точка портала: глава 10 стыкуется с кровлей и фасадом
  ровно в ноль (нулевой нахлёст прямоугольников строгое пересечение не прощает), и
  вынесенная на 1,4 м за фасад точка портала ловит не тот проём.
- Любая новая вертикаль обязана иметь **непрерывную цепочку маршей** от пола до
  этажа/кровли, иначе `_pruneToSpawn` отсечёт её решётку как изолированный карман
  (замерено: у башни с маршами [0,1] и [3,4] кровля исчезала из графа, а тест
  «одна связная сеть» этого не замечал — он считает то, что осталось). Проверка
  «узлы на кровле стоят на своей плите» обязана быть отдельной.
- Русло (`waterways`) — **отрицательная высота поверх «пола мира — ноль»**, и
  держится оно не солидами, а двумя механизмами сразу: планы дна, сходов и
  береговых стенок прорезают плиту грунта (`JsonMap.holes` → `_groundGeo()` и
  предикат `_inChannel`), а твёрдость отдадут призмы (`prisms`) — дно, склон
  берега и пандус схода. Солид во всю глубину русла дал бы невидимую коробку
  там, где глаз видит воду, а единая `PlaneGeometry` земли — фантомный пол над
  каналом: `groundHeightAt` возвращал бы ноль, и нога шла по воздуху. Поэтому
  над руслом опора — отметка призмы (дно ниже нуля), а `raySolid` для нисходящего
  луча, попавшего в `holes`, временно гасит `groundPlane`: пол мира выше дна, и
  луч обязан идти дальше — к стенке, дну или настилу. Отбрасывать уже готовое
  попадание нельзя: верх береговой стенки лежит ровно на отметке земли, и под тем
  же углом отбрасывался бы удар в стенку, а не в воду.
- Проходимость русла — свойство данных, а не кода: `wade: true` оставляет дно
  свободным (в него ведут сходы `ramps`, их обязано быть не меньше двух, иначе
  карниз стенки не отпускает обратно), `wade: false` ставит на дно блокер во всю
  глубину, и граф тогда обрывается у уреза воды — ни узла на дне, ни маршрута за
  реку. Уклоны берега и схода ограничены той же `J.maxSlope`, что и настилы
  дорог, а цепочка узлов вдоль уклона ставится чаще решёточного шага (ровно как
  на пролётах): `_link` не берёт перепад больше `stepUp`, и одним ребром склон
  не перейти. Луч и сфера идут по призме, нога — по её же аналитическому верху.
- Дом, вставший в план наземной улицы, бракуется; так же бракуется часть
  footprint в русле и наземная улица через русло — дорогу через воду делает
  мост. Опоры и фонари автогенерации не ставят ни в береговую стенку, ни в план
  схода, а пятку опоры над руслом парсер опускает на отметку дна
  (`waterwayFoot`), иначе колонна кончала бы на «нуле пола мира» и висела над
  водой.
- Картинка обязана расходиться с опорой там, где две грани уровня лежат в одной
  плоскости (со-плоскостные грани мигают в z-buffer): верх плиты пола комнаты —
  на `J.floorRise` выше её отметки (у первого этажа отметка равна земле), а верх
  картинки стены, упирающейся в кровлю, — на `J.roofSeam` ниже кровли. Коллизия
  при этом остаётся на настоящей отметке: срезанный солид стены пропустил бы
  идущего с крыши сквозь парапет, а опора обязана совпадать с картинкой, поэтому
  узлы графа ставят по фактической опоре (`_floorSupport` с допуском на шов).
- Район главы описывается данными (`asset`, `window`, `cell`, `scale`, `spawn`)
  — `ModelMap` строит из них сетку колонок, меш района, опоры и граф улиц; что
  именно можно извлекать из меша — см. раздел «Внешние ассеты уровня (GLB)».
  Глава на всём макете (`stream`) описывается теми же данными, только `window`
  задаёт первое окно, а `spawn` и `gameplay.exit` — метры масштабированной модели
  относительно его центра: точка B обязана лежать в покрышке окон, кратных тайлу
  от первого центра, иначе до неё просто нет дороги.
- Рельеф главы описывается данными (`hills`, `mountains`, `caves`, `chasm`,
  `ramps`, `bridge`, `flats`, `spawn`) — `TerrainMap` лишь строит из них
  геометрию, коллизии и граф навигации. Проходимый перепад клетки-фичи —
  `stepUp` (в навигации — `CONFIG.terrain.navStep`), всё выше — стена.
- Город главы описывается данными (`grid`, `block`, `street`, `curb`,
  `sidewalk`, `house`, `seed`, `spawn`) — `CityMap` строит из них кварталы,
  улицы, дома, коллизии и граф. Планировка детерминирована сидом. Тротуар
  квартала — опора на `curb` (меньше `stepUp`), а не солид: и ноги, и сфера
  Чужого перешагивают бордюр. Пол первого этажа дома обязан совпадать с верхом
  подиума — это `baseY` здания: все высоты (перекрытия, марши, коллизии, опоры,
  узлы графа) считаются от него, иначе точки полов и маршруты висят ниже своей
  опоры. Решётка навигации не заходит в габарит дома, а в дом и из дома ведёт
  порог входной клетки. Ребро графа обязана держать проба габарита вдоль всего
  отрезка (`SolidField.bodyClearLine`, шаг `CONFIG.nav.bodyProbe`): тонкий луч
  проходит в зазор у фасада, а тело — нет, и маршрут упирается в стену.
- Клетки рельефа, не тронутые фичами, получают опору, меш **и коллизию** из
  **аналитической поверхности** (`renderSub` подсетка на клетку): склон и
  выглядит, и обается гладко — без невидимой грани на границе колонок. Стена
  там, где поверхность растёт быстрее `CONFIG.terrain.climbSlope` (юнитов
  подъёма на юнит пути): `isBlocked` прощупывает поверхность по кольцу проб на
  расстоянии радиуса, `_buildNav` для пары поверхностных узлов меряет уклон
  вдоль отрезка между центрами. Физика и маршруты обязаны использовать один и
  тот же предел, иначе граф поведёт врагов сквозь стену. Флаги клетки говорят,
  что именно аналитично: `smoothFlags` — опора и коллизия из поверхности,
  `renderFlags` — клетка отдаёт сетку поверхности, `_hard()` снимает оба.
  Любая новая фича, правящая верх колонки, обязана позвать `_hard`, иначе опора
  разойдётся с вырезанной колонкой.
- Свод пещеры — исключение из «колонка значит стена»: `caves` делит клетку на
  пол и перекрытие и, если над проходом ещё порода, оставляет `roofFlags` и
  `caveCeil`. Такая клетка снова отдаёт поверхность (только выше `caveCeil`,
  ниже — по колонкам), так что гряда над туннелем гладкая и на вид, и на шаг, а
  ход под ней остаётся ходом. Верх перекрытия режут по **минимуму** поверхности
  клетки, иначе коробка пробьёт сетку; поверхность берут по **максимуму**,
  иначе горб у границы клетки перекроет устье. Стык с соседом закрывает «юбка»
  до постели — её не ставят только когда сосед сам рисует поверхность над
  сплошной породой, и никогда между двумя пещерными клетками (иначе панель
  перерезает коридор).
- Твёрдость рельефа обязана совпадать с картинкой: аналитический верх (грунт
  гладкой клетки и каменный панцирь над сводом) **не попадает в `solids`** — его
  держит `_rockAt`, а переопределённые `raySolid`/`resolveSphere` ищут породу
  маршем по `_surface` и выталкивают сферу вдоль нормали поверхности. Иначе под
  гладкой сеткой прячется лестница из вершин колонок (коробка = высота центра
  клетки): тело Чужого и пули опирались бы на ступени, которых глаз не видит.
  Панцирь над сводом режут не тоньше `roofCap`, а нехватка хода на `caveMinHeight`
  превращает клетку в прорез-выемку без перекрытия — иначе под нарисованным
  склоном остаётся невидимая плита тоньше человека, в которую идущий проваливается.
- Колоночные фичи (площадки, откосы, пропасти, мосты) остаются как раньше — их
  перепад и должен быть стеной. Пол и потолок вырезанного хода тоже остаются
  коробками: внутри хода тело держат они, а не поверхность горы.
- Следствие для глав-переходов: пологий хребет проходной в любом месте, поэтому
  туннель — самая короткая и подсказанная дорога, а не единственный путь. Если
  главе нужен обязательный проход, уклон в данных должен быть больше
  `climbSlope` (отвес) или породу должен резать `caves`, а не только `chasm`.
- Прямоугольник пещеры (`caves`) режет породу только внутри себя, поэтому его
  край обязан выходить на клетки, чья высота не больше `floor + stepUp`: иначе
  за устьем остаётся глухая скала и ход превращается в тупик. Пол пещеры
  выбирают по заходным площадкам (`flats`), а проходовость проверяет тест
  «шаг по поверхности» в `tests/terrain-traverse.test.js`.
- Пропасть (`chasm`) режет дно либо на `depth` ниже поверхности, либо до
  постоянной отметки `floor`. Дну лучше иметь `floor`: неровное дно колонками
  даёт карманы, из которых нет выхода, а плоское дно гарантирует, что откос
  досягаем с любой точки. Откос, идущий под настилом моста, обязан начинать
  ниже дна и набирать высоту пологим шагом — иначе под пролётом остаётся
  карниз, а не маршрут, и падение в пропасть становится ловушкой.
- Запрещено хардкодить содержимое конкретного уровня в `game.js`, `map.js`,
  `terrain-map.js`, `enemies.js`, `decor.js`. `config.js` — только значения
  по умолчанию.
- Геометрия уровня и декор детерминированы: рандомизация через ГПСЧ с сидом из
  определения уровня (разброс монет может использовать `Math.random`).
- Прохождение главы — цель из определения (`goal: 'exit'` — дойти до точки B,
  `goal: 'coins'` — собрать все монеты); далее игра загружает следующую главу
  без перезагрузки страницы. Смерть перезапускает текущую главу.

## Сущности и жизненный цикл

- `Game` пересоздаёт сцену и все сущности при загрузке уровня. Класс, вешающий
  слушатели на `window`/`document`, ОБЯЗАН иметь `dispose()` и сниматься при
  выгрузке уровня (см. Player, Alien, Weapon).
- Новые слушатели без возможности снятия — блокирующее замечание при ревью.
- Переход Чужого между поверхностями сохраняет линию взгляда в мире (`_beginTransition`)
  — это нужно для переворота потолок ↔ пол: иначе после скачка на пол камера
  смотрит вверх и тело само залезает назад на потолок. Исключение — **перевал со
  стены на горизонталь**: там взгляд переносится поворотом корпуса. Подъём по стене
  требует `pitch > climbPitch`, то есть на стене взгляд откинут вдоль её нормали —
  наружу; сохранённая в мире линия после перевала ставит «вперёд» ОТ здания, и с
  зажатым «вперёд» тело сходит с только что взятой кромки и сползает назад. На
  строении с уступами (в районе главы 3 их 196 со 2–3 уступами) это обрывало
  подъём на каждой полке.

## Тесты

- Изменения физики, коллизий, навигации или контракта карты проверяются
  браузерными автотестами `tests/*.test.js` (запуск из консоли страницы игры).
  Работа не считается завершённой без зелёного прогона.
- Новая механика — новый автотест в том же заходе.

## Стиль

- Русские doc-комментарии в формате «что + почему»; тривиальный код не комментируем.
- UI только через `src/hud.js`; остальные модули не трогают DOM (кроме
  переданного `domElement` для pointer lock). Единственное осознанное исключение —
  отладочная панель `src/debug.js`: монтируется только при `?debug=1`, игровым
  процессом не управляет и не участвует в тесте.
- Метки id объектов в мире (`?debug=1`) рисует панель, но точки для них обязана
  отдавать карта через второй опциональный член контракта — `debugIds()` →
  `[{ text, x, y, z }]`. Текстом идёт id из брифа плюс различающий суффикс
  (`· эт 2`, `· spiral`, `· пл 3 · наклон`), потому что одна пластина дороги и её
  наклонный пролёт живут в одном файле под одним id. Пересобирать схему уровня в
  `debug.js` запрещено: панель не знает ни номеров глав, ни нормализатора —
  иначе арифметика путей продублировалась бы в двух местах и разошлась при
  первой же правке схемы. Метки — объекты сцены, поэтому обязаны сниматься и
  `dispose()`-нить текстуры/материалы при выключении и перестраиваться после
  загрузки главы (`_buildLevel` создаёт новую сцену).
- Настраиваемые значения — в `config.js` (по умолчанию) и в определении уровня
  (переопределения); числа не дублируются в модулях.
- Коммиты: `feat:` / `fix:` с одной строкой о причине изменения (см. git log).
